# 产品化路线（尚未实现）｜从决策引擎到机构级工作台

> **状态说明**：本文描述的是**路线与边界**，不是已交付的功能。
> 仓库当前可运行的是 L0–L5 决策引擎与走查式回测；下文中提到的 Web 工作台、
> 真实数据接入、模型信号层**都还没有实现**。写在这里是为了说清方向，
> 避免把"设想"读成"现状"。

## 1. 现在能跑的是什么

两条流水线，都是零依赖可执行：

```bash
# 单期：取数 → 约束 → 研究 → 配置 → 闸门 → 报告与审计
python -m ins_am_agent --out examples/sample_report.md

# 多期：走查式回测，策略与「不调仓」基准对照
python -m ins_am_agent --pipeline pipeline.backtest.yaml --out examples/backtest_report.md
```

| 层 | 现在实现了什么 | 代码位置 |
| --- | --- | --- |
| L0 平台底座 | 配置驱动流水线、组件注册表、YAML 子集解析 | `ins_am_agent/platform/`、`pipeline.yaml` |
| L1 数据与状态 | JSON 适配器、质量校验、组合状态与调仓流水、合成历史 | `ins_am_agent/data_layer/` |
| L2 约束与政策 | 约束唯一来源、规则归属与触限处置、装载 fail closed | `ins_am_agent/policy/` |
| L3 投研 | 四个研究员 + 交叉质询 + 失效条件（注册表可换） | `ins_am_agent/agents/b_research.py` |
| L4 配置引擎 | 久期缺口、压力测试、目标权重、成本与偏离理由 | `ins_am_agent/agents/c_allocation.py` |
| L5 治理与交付 | 闸门、签批、报告、审计留痕、回测报告 | `ins_am_agent/agents/d_*.py`、`evaluation/` |

## 2. 边界表：已实现 / 规划中 / 明确不做

| 能力 | 现在 | 规划中 | 边界 |
| --- | --- | --- | --- |
| 数据接入 | JSON 文件 + 合成历史 | 接数仓、估值、精算与偿付能力系统 | 公开仓库只用合成数据 |
| 投研观点 | 确定性规则实现 | 接私有知识库与 LLM，规则与模型可混用 | 数字仍由代码算 |
| 配置求解 | 规则式调仓（顺序补丁） | 目标函数 + 约束求解器，输出「为什么是这个权重」 | — |
| 资本约束 | 比例与限额（示意值） | Solvency II / 香港 RBC / 偿二代三类口径 | 示意值不是监管口径 |
| 评估 | 回测、归因、策略 vs 基准 | 覆盖率、约束违反率、文本与数字一致性 | — |
| 闸门与签批 | 规则引擎 + 政策文件驱动 | 接审批与权限系统 | 人签批不可替代 |
| 交易执行 | **明确不做** | — | Agent 不接触交易接口 |
| Web 工作台 | **未实现** | 内部前端应用（组合、归因、压力测试、审批留痕） | 不替代已有交易与估值系统 |

## 3. 角色与责任

| 角色 | 代码位置 | 主要任务 | 人的责任 |
| --- | --- | --- | --- |
| 数据与质量 | `data_layer/` | 取数、时点对齐、质量报告 | 抽查口径与数据时点 |
| 政策与约束 | `policy/`、`config/constraints.yaml` | 限额、久期、流动性、换手，规则的归属与处置 | 定义与维护限额，说明来源 |
| 宏观 / 信用 / 权益 / 另类研究 | `agents/b_research.py` | 观点、证据、置信度、失效条件 | 采纳、否定、补充判断 |
| ALM 与组合计算 | `agents/c_allocation.py` | 久期缺口、压力测试、目标权重、成本 | 定义约束与目标函数 |
| 风控合规闸门 | `agents/d_gate.py` | 限额、集中度、流动性校验，四档结论 | 批例外、否决或升级 |
| 报告与审计 | `agents/d_report.py` | 决策报告、审计记录、指纹 | 签发正式材料 |
| 回测与评估 | `evaluation/` | 净值、归因、与不调仓基准对照 | 判断结论是否可采信 |

## 4. 工程化顺序（下一步做什么）

按「能不能回答一个具体问题」排序，而不是按好不好看排序：

1. **回测与评估**（已完成）——回答「这套调仓逻辑比什么都不做差在哪」。
2. **配置求解器**——把 L4 从顺序补丁换成「目标函数 + 约束」，回答「为什么是这个权重」。
3. **评估体系扩展**——约束违反率、覆盖率、文本与数字一致性，回答「怎么证明它可靠」。
4. **真实数据适配器**——先用公开数据（如国债收益率曲线）替换合成历史，验证接口。
5. **Web 工作台**——最后做。它是对外呈现层，不能反过来替代前四步的证据。

## 5. 不变的边界

- 人保留**签批**与**下单**两处责任，Agent 不接触交易接口。
- 每个观点必须带**失效条件**；每个结论必须可复现（输入指纹 + 政策指纹 + 状态指纹）。
- 公开仓库只用合成数据，不出现任何机构内部数据、系统名与字段名。
